# scripts_other_team

Tampermonkey-скрипты для TH Management. Скрипты **обновляются сами**: Tampermonkey периодически сверяет версию по ссылке из шапки скрипта и подтягивает новую.

## Установка

Открыть ссылку в браузере с установленным [Tampermonkey](https://www.tampermonkey.net/) и подтвердить установку:

- [TH Management — Состояние тикетов](https://raw.githubusercontent.com/partenkoEgor/scripts_other_team/main/scripts/th-ticket-state.user.js)

После установки проверить в панели Tampermonkey, что скрипт **включён** (переключатель в списке), и перезагрузить вкладку с админкой.

## Состояние тикетов

`scripts/th-ticket-state.user.js` — текущая версия: **1.1**. Работает на странице **List of payment queries** (`…/en/admin/backoffice/paymentsupport`) на трёх доменах: th-managment.com, managment.io, my-managment.com.

### Что делает

По списку Ticket ID показывает **текущее состояние** каждого тикета:

| Колонка | Что это |
|---|---|
| Ticket ID | номер тикета |
| External Status | внешний статус тикета |
| Transaction ID | номер транзакции в тикете (пусто, если его нет) |
| Inside comment | внутренний комментарий |
| Agent's files | «пусто», «N файлов» или «нет данных» (сайт не прислал эту колонку) |
| User ID | ID пользователя |
| ГЕО | ГЕО тикета |
| Реферал | реферал тикета |
| Агент | агент тикета |
| Субагент | субагент тикета |

**Скрипт только читает**: окна Edit не открываются, в тикетах ничего не меняется.

### Как пользоваться

1. Открыть страницу **List of payment queries**.
2. Нажать кнопку **«Состояние тикетов»** слева внизу.
3. Вставить список Ticket ID — **по одному номеру в строке** — и нажать **«Проверить список»**. Или нажать **«Проверить экран»** — тогда проверятся тикеты, которые сейчас в таблице.
4. Дождаться отчёта. В нём:
   - **сводка** — сколько тикетов в каждом External Status, у скольких заполнен Transaction ID, у скольких есть Agent's files;
   - **таблица текстом** с кнопкой «Скопировать» — вставляется в Excel или Google Таблицы как есть (табуляции и переносы строк из комментариев заменены пробелами);
   - кнопка **Excel** — файл `sostoyanie-tiketov_<дата>_<время>.xlsx`:
     - первый лист **«Тикеты»** — все тикеты, строки в порядке вашего списка;
     - дальше **по листу на каждый External Status** (от самого частого к редкому) — те же колонки, только тикеты с этим статусом. Тикеты без статуса — на листе «Без статуса»;
     - если какие-то тикеты сайт не нашёл — последний лист **«Сайт не нашёл»**.

### Если что-то не так

- **«Сайт не нашёл по фильтру»** — тикет не попал в выдачу с фильтрами, которые сейчас стоят на странице (даты, статусы, отдел и т. п.). Такие тикеты тоже есть в таблице и файле, с пометкой. Снимите лишние фильтры и проверьте снова.
- **«Сессия истекла»** — сайт вместо данных ответил страницей входа. Обновите страницу, войдите заново и повторите.
- **«Не удалось подхватить запрос…»** — нажмите **Apply** у фильтров страницы и попробуйте снова.
- **«нет данных» в ГЕО, Реферал или Агент** — в ответе сайта не нашлось такого поля. Скрипт ищет его по известным названиям (`nameGeo`, `nameReferral`, `nameAgent` и т. п.), а если их нет — по любому полю со словом geo/country, refer или agent в названии. Список полей, которые прислал сайт, скрипт пишет в консоль (F12) строкой `[TicketState] Поля в строке ответа сайта: …` — по нему видно, как поле называется на самом деле, и его можно добавить в `EXTRA_FIELDS` в начале скрипта.
- В первый раз скрипт сам нажимает **Apply** у фильтров: так он узнаёт, каким запросом страница грузит таблицу. Фильтры при этом не меняются.

### Как это устроено

Таблицу страница грузит одним запросом со всеми фильтрами. Скрипт запоминает этот запрос (со всеми заголовками) и повторяет его, подставляя только свои номера тикетов, пачками по 100, с паузами и повторами, если сайт перегружен. Других запросов к сайту он не делает.

Скрипт уживается на одной странице с Bulk Approve и Team Helper (репозиторий [partenkoEgor/Monitoring](https://github.com/partenkoEgor/Monitoring)): у него свои кнопка, окна и классы на странице, а свои запросы он отправляет мимо журнала запросов Bulk Approve, так что прогонам не мешает.

Код перенесён из кнопки «Состояние тикетов» беты Bulk Approve в репозитории Monitoring. Там же лежат тесты, которые проверяют этот скрипт (сценарий 29 в `tests/bulk-approve/`, нужен клон этого репозитория рядом с Monitoring).

## Обновление скрипта

1. Внести изменения в `scripts/th-ticket-state.user.js`.
2. Увеличить `@version` в шапке скрипта — без этого Tampermonkey не увидит обновление.
3. Запушить в `main`.

Чтобы получить обновление сразу: значок Tampermonkey → **Check for userscript updates**, затем перезагрузить вкладку с админкой.
